## 一、结论（先回答"能不能通过安装包直接攻击安装者"）

**不能直接攻击，但存在两条可以间接拿下的供应链链路。**

| 攻击方式 | 可行性 | 说明 |
|---|---|---|
| 安装包里藏恶意代码，一装就中招 | ❌ 未发现 | 包内只有 Electron 官方运行时 + 我们的 app.asar，无可疑可执行文件、无自解压脚本 |
| 安装时静默提权 / 静默执行外部程序 | ❌ 未发现 | per-user 安装（`asInvoker`），不申请管理员；安装结束只创建快捷方式 |
| 借安装包做"钓鱼分发"（改包后放伪造下载页） | ✅ 可行 | **未做代码签名**，用户无法分辨真假包 |
| 通过自动更新通道推恶意包 | ✅ 可行（理论） | 清单与安装包同源，`sha256` 也来自同一响应；服务器被拿下 ⇒ 所有用户静默执行任意安装包 |
| 通过 Java 运行时下载投毒 | ✅ 可行 | JRE 从镜像下载后**无哈希校验**就解压执行 |

**一句话**：当前安装包本身是干净的；风险全部在"它运行之后从网上拿回来的东西"。

## 二、安装包静态检查

### 2.1 数字签名

```
Get-AuthenticodeSignature → NotSigned
```

- 无签名 ⇒ 无 SmartScreen 信誉、无法判断是否被篡改、Windows 首次运行弹"未知发布者"
- 也意味着**更新链路无法用签名做二次校验**

| 组件 | 说明 |
|---|---|
| `$PLUGINSDIR\app-64.7z` | 81.4 MB，全部程序文件（唯一实际载荷） |

| `$PLUGINSDIR\modern-wizard.bmp` | 安装向导图片 |
| `$R0\Uninstall RAINBOW MC.exe` | 卸载器（122 KB） |

**无自定义 VBS/BAT/PS1，无 `nsExec` 调用外部下载器的痕迹。**

### 2.3 解包后的可执行文件（共 8 个，全部可解释）

### 2.4 安装行为

- `requestedExecutionLevel = asInvoker`，`perMachine=false` ⇒ **装到用户目录，不申请管理员**
- `customInit` 里有跨目录安装保护（`/S` 静默模式可绕过，但只影响安装位置，不构成提权）
- 卸载器只删程序文件，`data/` 不动（设计如此，已多次验证）

## 三、运行期联网链路审计

### 3.1 自动更新（高风险）

```js
// update.ts：downloadInstaller()
const res = await fetch(latest.downloadUrl, ...)        // 地址来自服务器清单
...
if (latest.sha256 && sha256File(file) !== latest.sha256) 删除并报错
// runInstaller()
spawn(installerPath, ['/S', '/KEEPDATA', `/D=${dir}`], { windowsVerbatimArguments: true })
```

- `sha256` 由**同一份清单**提供 ⇒ 只能防传输损坏，**不能防服务器被攻陷**
- 拿到服务器控制权 ⇒ 改清单 + 换包 ⇒ 用户点"更新"后**静默安装并执行任意代码**
- 这是本次审计里唯一能达到"直接控制安装者电脑"的链路

### 3.2 Java 运行时下载（中高风险）

```js
const mirrors = [tuna, nju];  // 清华 / 南大镜像
const { url } = await adoptiumUrl(major);
await downloadOne({ url: candidate, dest: zipPath });  // ← 无哈希校验
zip.extractAllTo(dest, true);
```

- 下载 `jre-x64-windows.zip` 后**直接解压并把它当作 javaw.exe 执行**
- 镜像站被投毒 / 供应链劫持 ⇒ 启动游戏时执行任意代码
- 三个来源（TUNA / NJU / Adoptium GitHub）都没有固定哈希

### 3.3 Terracotta（安全）

```js
const WIN_EXE_SHA256 = '74c10568…'
if (digest !== WIN_EXE_SHA256) 拒绝
```

✅ 二进制 SHA256 已固定，且解压后又校验一次。

### 3.4 Forge 安装器（中低风险）

```js
downloadInstaller(FORGE_MAVENS.map(b => `${b}/${path}`), jar)
runInstaller(jar, ...)   // java -jar forge-installer.jar --installClient
```

- 从 maven 下载 `forge-*-installer.jar` 后 `java -jar` 执行，**无哈希校验**
- Forge 官方 maven 会提供 `.sha1`，但当前未使用

### 3.5 整合包 / 模组（用户主动行为）

- 整合包解析用 `adm-zip@0.6.1`（较新，含 GHSA-p634 重复条目修复）
- 模组 jar 不校验签名/哈希 —— 这是所有启动器的通例，风险由"用户自己导入来源"决定

## 四、应用内接口暴露

| 项 | 现状 | 风险 |
|---|---|---|
| `nodeIntegration` | `false` | ✅ 好 |
| `contextIsolation` | `true` | ✅ 好 |
| `sandbox` | **`false`** | 中低：渲染进程未沙箱，将来若引入远程内容会放大风险 |
| `will-navigate` | 外部 URL 一律 `preventDefault` + 交给系统浏览器 | ✅ 好 |
| `setWindowOpenHandler` | 一律 deny + 外部打开 | ✅ 好 |
| `rainbow://` 协议 | **仅字符串前缀判断**：`file.startsWith(root)` | ⚠️ 中：`…\data\..\..\Windows\win.ini` 这种字符串仍以 root 开头，可绕过读取任意文件（限图片 MIME） |
| `open:path` | `shell.openPath(p)`，路径不限 | 低：渲染层若能注入，可打开任意文件/程序（`.exe` 会被执行） |
| 主控台命令 | 固定命令表，无 `exec`/`shell` 执行 | ✅ 好 |
