## 二、发现并修复的缺陷

### 缺陷 1（严重）：升级后卸载信息指向旧目录

- **现象**：安装器模板只在**首次安装**写 `UninstallString` / `QuietUninstallString` / `DisplayIcon`，升级时不重写。
- **后果**：如果安装位置变过，之后的「卸载」会去删**旧目录**的程序文件；本次测试中就因此把真实安装 `D:\APP\RAINBOWMC` 的 exe 删掉过一次（data 完好）。
- **修复**：`build/installer.nsh` 的 `customInstall` 里补写全部卸载键（`DisplayName / DisplayVersion / Publisher / DisplayIcon / UninstallString / QuietUninstallString / NoModify / NoRepair`），每次安装都刷新。
- **验证**：0.3.9 安装后注册表 10 个键全部指向 `D:\APP\RAINBOWMC`，`DisplayVersion = 0.3.9`。

### 缺陷 2（中等）：更新完成提示读不到标记

- **现象**：`update:consumeUpdated` 用 `require('../update')`，打包后取不到模块 → 返回值恒为 `undefined`；另外 PowerShell 写出的 JSON 带 BOM 会让 `JSON.parse` 抛错。
- **后果**：「更新完成」弹窗与结束音不出现。
- **修复**：改为**静态 import**；读取 `updated.json` 时剥离 BOM。
- **验证**：标记被正常消费，完成弹窗出现并停留约 3.5 秒。

## 三、为什么 data 不可能被覆盖

1. `customRemoveFiles` 只删**程序本体**（exe/dll/pak/resources/locales），从不 `RMDir /r $INSTDIR`；
2. `customUnInstall` 有意留空，卸载不碰 `data\`；
3. `customInstall` 只 `CreateDirectory` 建缺失的 `data\*` 子目录，不覆盖已有文件；
4. 应用更新走 `/KEEPDATA`，且安装前校验「注册表 InstallLocation == 当前目录」。

## 四、剩余风险（已记录，未触发）

| 风险 | 说明 | 缓解 |
|---|---|---|
| 手动改注册表后再装到别的目录 | 旧卸载器仍按 `UninstallString` 删旧目录程序文件 | 定制脚本已保证每次安装刷新卸载键；正常使用不会出现 |
| 安装中断电 | 可能出现程序文件半新半旧 | data 不受影响；重装即可 |
| 存档被游戏本身损坏 | 与安装无关 | 已有 `F:\RAINBOWMC-存档备份_*` 备份 |
