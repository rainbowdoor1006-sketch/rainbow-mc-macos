> 读者：彩虹门社团网站 AI / 运维
> 日期：2026-10-22
> 对应客户端：`RAINBOW MC 0.1.0`（versionCode 10）
> 目标：完成第一次真实更新闭环 —— 客户端启动 → 提示 0.2.0 → 下载 → 静默覆盖安装 → 存档不丢 → 自动重启

## 0. 一句话流程

```
拿到 setup.exe → 算好 sha256/size（工具自动算）→ 用 launcher-release.js 发布 0.2.0
→ 接口自动返回 0.2.0 和 setup.exe 的下载地址 → 客户端弹更新 → 下载安装
```

**不需要改接口代码**，只需要发布一条记录。

## 1. 前置：客户端已确认的契约（不用改，仅供核对）

```http
GET https://rainbowdoor.icu/api/launcher/version
X-Launcher-Channel: stable
```

```json
{
  "ok": true,
  "channel": "stable",
  "latest": {
    "version": "0.2.0",
    "versionCode": 20,
    "downloadUrl": "https://rainbowdoor.icu/launcher/RAINBOWMC-0.2.0-setup.exe",
    "sha256": "…",
    "size": 81849668,
    "publishedAt": "2026-10-22 …",
    "notes": "…",
    "mandatory": false,
    "minSupported": ""
  },
  "installer": { "type": "nsis", "silentArgs": "/S", "keepDataArgs": "/KEEPDATA" }
}
```

客户端只认这几个字段，**字段名一个都不能改**：

| 字段 | 客户端怎么用 |
|---|---|
| `version` | 显示用，必须 `MAJOR.MINOR.PATCH` |
| `versionCode` | **比较用**（`MAJOR*100+MINOR*10+PATCH`） |
| `downloadUrl` | 直接 GET 下载，必须 HTTPS |
| `sha256` | 下载后必须校验，不匹配客户端会删文件并报错 |
| `size` | 进度条分母 |
| `notes` | 弹窗正文，纯文本，≤200 字 |
| `mandatory` | `true` 时客户端隐藏「不用了，谢谢」 |

## 2. 发布 0.2.0 的具体操作

### 2.1 把文件放到服务器

```bash
# 本地 → 服务器
scp RAINBOWMC-0.2.0-setup.exe root@<你的服务器>:/root/build/

# 确认文件完整（对比本地 sha256）
sha256sum /root/build/RAINBOWMC-0.2.0-setup.exe
```

### 2.2 用发布工具登记（它会自动算 sha256/size 并复制文件）

```bash
cd /opt/rainbow-site/server

node tools/launcher-release.js --add \
  --channel stable \
  --version 0.2.0 \
  --code 20 \
  --file /root/build/RAINBOWMC-0.2.0-setup.exe \
  --notes "新增自动更新、NSIS 安装程序、整合包导入自动装加载器"

# 看看发出去没有
node tools/launcher-release.js --list
```

期望输出：

```
id   渠道       版本        code   大小          强制    启用    发布时间
2    stable   0.2.0      20     78.1 MB      否     是     2026-10-22 …
1    stable   0.1.0      10     71.1 MB      否     是     2026-10-22 …
```

> 工具默认 `is_active` 的**最新 version_code 才生效**，旧记录保留但不会被返回。

### 2.3 立刻验证公网接口

```bash
curl -s -H "X-Launcher-Channel: stable" \
     -H "User-Agent: RAINBOWMC/0.1.0 (win32; x64)" \
     https://rainbowdoor.icu/api/launcher/version | python3 -m json.tool
```

**必须看到：**

- `latest.version` = `0.2.0`
- `latest.versionCode` = `20`
- `latest.downloadUrl` 结尾是 **`RAINBOWMC-0.2.0-setup.exe`**（不是 portable.exe）
- `latest.sha256` 与 `sha256sum` 的结果**一致**
- `latest.size` = 文件实际字节数

### 2.4 验证下载真的能下

```bash
curl -sI https://rainbowdoor.icu/launcher/RAINBOWMC-0.2.0-setup.exe
# 期望：HTTP/2 200 / content-type: application/octet-stream
#       content-length: 81849668 / accept-ranges: bytes
```

⚠️ **注意你们上次踩过的坑**：nginx 有两个 server 块（443 直连 + 127.0.0.1:80 隧道）。
新增静态目录时**两个块都要加 `location /launcher/`**，否则公网会返回首页 HTML，客户端下载到的是 HTML → sha256 校验失败。

验证方法：

```bash
curl -s https://rainbowdoor.icu/launcher/RAINBOWMC-0.2.0-setup.exe | head -c 2
# 期望输出 "MZ"（exe 文件头）。如果输出 "<!" 或 "<html>"，说明 nginx 配错了
```

## 3. 客户端拿到后会做什么（服务端不用管，但要知道预期）

```
1. 启动器启动 → GET /api/launcher/version（8 秒超时，失败静默）
2. versionCode 20 > 本地 10 → 弹「发现新版本 0.2.0」，显示 notes 与 size
3. 用户点「立即更新」→ 下载 downloadUrl（带 Range 断点续传）
4. 校验 sha256 → 不匹配：删除文件 + 报错「安装包校验失败」
5. 静默执行：setup.exe /S /KEEPDATA /D=<当前安装目录>
6. 安装完自动重启启动器
```

**用户点「不用了，谢谢」** → 客户端记住 `skippedVersion=0.2.0`，**同一个版本不再提示**，直到下一次版本号变化。

## 4. 想强制更新 / 灰度怎么办

| 需求 | 做法 |
|---|---|
| 必须升级 | 发布时加 `--mandatory`，客户端隐藏「不用了，谢谢」，只给「立即更新」 |
| 先小范围试 | 先发到 `beta` 渠道，观察 1–2 天再发 `stable` |
| 撤回某个版本 | `node tools/launcher-release.js --disable 2`，接口会自动回落到上一条启用记录 |

> `beta` 渠道客户端默认不走（设置里「更新渠道」默认 stable）。要让人测 beta，得手动改成 beta。

## 5. 注意事项（容易炸的地方）

1. **文件名必须和 `--file` 一致**，`downloadUrl` 由工具按文件名生成，改名会导致 404
2. **不要重复发布同一个 version_code**：客户端按 code 比较，重复会导致行为不确定
3. **sha256 必须严格小写十六进制**，客户端按小写比对
4. **换文件必须重新发布**：直接替换服务器上的同名文件会导致 sha256 与库里不一致 → 所有客户端更新失败
5. **发布后清一下 Cloudflare 缓存**（`/api/launcher/version` 若被缓存，客户端会一直看到旧版本）
   - 你们的响应头是 `Cache-Control: no-cache`，正常不会被缓存；但发布后仍建议 purge 一次
6. **1.55 GB 的整合包别放这台 ECS**（你们文档里也说了），启动器安装包 80 MB 没问题

## 7. 回滚预案

```bash
# 0.2.0 有问题 → 停用它，接口立刻回到 0.1.0
node tools/launcher-release.js --disable 2

# 验证
curl -s -H "X-Launcher-Channel: stable" https://rainbowdoor.icu/api/launcher/version | grep version
```

> 已经升到 0.2.0 的用户不会被降级（客户端只在「线上更新」时才提示），
> 所以**发 0.2.1 修复**比回滚更有效；回滚只用于阻止还没升级的用户继续升级。
