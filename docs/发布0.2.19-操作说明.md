## 2. ⚠️ version_code 需要你定

我们的规则是 `MAJOR*100 + MINOR*10 + PATCH`，这套规则只适合 `0.x.0` 这种小版本号。
现在版本号到了 `0.2.19`，按公式算 `0*100 + 2*10 + 19 = 39`，**比 0.2.9 的 29 大，逻辑没问题**，可以继续用。

两种选择：

| 方案 | version_code | 说明 |
|---|---|---|
| **A（推荐）** | `39` | 沿用公式 `0*100+2*10+19`，接口按 code 排序，39 > 29 正确 |
| B | `219` | 自己定一个更大的号，只要比历史记录大即可 |

**我这边客户端没写死 code，是运行时按版本号算的**，所以无论你选哪个，客户端都算得出来——
但前提是**服务端返回的 versionCode 必须和公式一致**，否则会出现「本地 0.2.19(39) vs 线上 0.2.19(219)」误判成“先行版”。

👉 **建议用 A（39）**。

## 5. 修复清单（0.2.10 → 0.2.19）

### 🔴 严重（会丢数据 / 会阻断更新）

| 版本 | 问题 | 修复 |
|---|---|---|
| **0.2.13** | **安装/覆盖时会删除 `data/`**——安装脚本里 `RMDir /r "$INSTDIR\data"` 把旧卸载程序刚还原的存档又删了一遍，实机丢过 4.7 GB 数据 | 重写安装脚本：**只删程序文件**（exe/dll/pak/resources/locales），`data/` 从始至终原地不动 |
| **0.2.9** | 大存档（~5 GB）升级时安装卡在进度条一半 | 同上前提 + 搬迁逻辑改为 `Rename` 优先、失败才 `robocopy`；实测 4.7 GB 从“卡死”变 **7 秒** |
| **0.2.7** | 点「立即更新」后**安装程序不启动**（0.2.6 引入的 `cmd` 包装 bug） | 恢复直接拉起安装器，启动器 1.5 秒后自行退出 |
| **0.2.8** | 安装路径含空格时 `/D` 被截断，装到错误目录（如 `...\RAINBOW` 而不是 `...\RAINBOW MC`） | spawn 加 `windowsVerbatimArguments`，`/D=` 后不加引号 |

### 🟠 功能缺陷

| 版本 | 问题 | 修复 |
|---|---|---|
| **0.2.10** | 只装过 A 版本再去跑 B 版本会因缺共享库直接崩（`java.lang.module.FindException: Module org.apache.logging.log4j not found`） | 新增 `ensureVersionFiles()`：**启动前 / 导入后自动补齐**缺失的库、客户端 jar、log4j 配置 |
| **0.2.14** | **没有项目时无法下载组件**（下载页整页显示“请先创建一个项目”） | 下载不再依赖项目；默认「不限版本/不限加载器」，只有勾选 **「按当前项目筛选」** 才套用项目条件 |
| **0.2.18** | 组件详情里点某个版本 → **整屏白屏**（`targetLoader.toUpperCase()` 对 undefined 调用） | 三处 props 全部判空；并新增**全局 ErrorBoundary**，以后任何页面异常都显示错误信息+重试，不再白屏 |
| **0.2.19** | 前置组件明明在组件库、详情页仍显示「缺失」；点补全又提示“跳过”——两处判断不一致 | 「已安装」改为 **项目目录 + 组件库** 双来源判断 |
| **0.2.11** | 装到与现有安装不同的目录时，会把旧安装的程序文件删掉（数据不丢但另一个安装报废） | 检测到不同目录先清掉旧卸载登记（**已知限制**：仍不建议同时装两份，见 §7） |

### 🟡 体验 / 显示

| 版本 | 问题 | 修复 |
|---|---|---|
| 0.2.12 | 覆盖安装数据搬迁用 `CopyFiles` 极慢 | 改用 `robocopy /MOVE`（多线程） |
| 0.2.15/16 | 无项目时下载页白屏（我改 0.2.14 时漏判空的 3 处） | 全部加判空 |
| 0.2.17 | 侧栏底部版本号**硬编码 v0.1.0**，日志 meta `launcherVersion` 也硬编码 | 全部改读 `app.getVersion()` |
| 全版本 | 整合包下载顺序按 index，最后被单个大文件拖尾，看起来像卡住 | 按文件大小**降序下载**（大文件先下） |

## 6. 安装器现在的行为（可以放心）

```
· 覆盖安装：只删程序文件，data/ 原地不动
· 数据目录：<安装目录>\data\（存档、组件库、游戏版本、加载器、资源、日志）
· 卸载：data/ 原样保留（重装即用）
· 静默升级：客户端自动更新时 /S 安装，装完自动拉起启动器
· 语言：默认繁體中文（LCID 1028），可切换简中 / English
```

已实测（同一台机器、4.7 GB 存档 / 11 个项目）：

```
0.2.6 旧安装器：卡死 >120 秒
0.2.19 新安装器：7 秒完成，数据完整、无残留备份
```

## 7. 已知限制（需要在网站公告里提一下）

1. **不要在同一台机器上装两个不同目录的 RAINBOW MC** —— 会互相删程序文件（数据不会丢，但那个安装要重装）
2. **安装路径尽量不含空格** —— 虽然 0.2.8 起修了，但带空格的路径在个别环境仍可能出问题，推荐 `D:\APP\RAINBOWMC` 这种
3. 只有 **0.2.6** 的用户需要手动下载一次（0.2.7 起已修；0.2.8 从未发布）
