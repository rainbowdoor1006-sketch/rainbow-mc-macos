# 服务端操作说明：把 0.2.0 的发布包替换成新构建（含新 SHA-256）

> 读者：彩虹门社团网站 AI / 运维
> 日期：2026-10-22
> 背景：客户端侧修复了 4 个 bug（静默安装卡死、许可页乱码、缺语言选择、`/D` 被忽略），
> **安装包重新构建了，sha256 和 size 都变了**，服务端库里那条 0.2.0 记录已经对不上文件。

---

## 0. 一句话

```
服务器上的 RAINBOWMC-0.2.0-setup.exe 要换成新文件，
launcher_releases 里 id=2 那条的 sha256 / size 也要同步改，
否则所有客户端下载后会「sha256 校验失败」并被删除。
```

新旧对比：

| 项 | 旧（已发布） | 新（要替换成这个） |
|---|---|---|
| 文件大小 | 81,849,698 | **81,852,307** |
| sha256 | `f11bc1e563fdc4125bb1d06cfb0ef35658d2592fae0ea91648976ac5bfd4223c` | `fa9521e09dce42717e51f66aa37c3358103021b7d083eaa87814e0a5506ad529` |
| 版本号 | 0.2.0 / code 20 | 同（见下方方案选择） |

---

## 1. 选一个方案

### 方案 A（推荐）：发 0.2.1 / code 21

理由：**同一个 version_code 对应不同内容**会让「已经下载过旧包的客户端」行为不确定，
而且没法区分「用户装的是修复前还是修复后」。

- 服务端：新增一条 0.2.1 记录
- 客户端：我看到发布结果后，把 `package.json` 提到 0.2.1 重新出包（下次构建）

### 方案 B（省事）：原地替换 0.2.0 的文件与哈希

适用于：目前**只有你自己在测试**，没有真实用户装过旧 0.2.0。

- 服务端：覆盖文件 + 更新 id=2 的 sha256/size
- 客户端：不用改版本号

> 下面两套步骤都写全了，按选定的方案做其中一套即可。

---

## 2. 文件放哪里

```
/opt/rainbow-site/launcher/RAINBOWMC-0.2.0-setup.exe     ← 静态文件（nginx 直接对外）
```

对应公网地址：

```
https://rainbowdoor.icu/launcher/RAINBOWMC-0.2.0-setup.exe
```

nginx 配置（**两个 server 块都要有**，你们上次踩过）：

```nginx
# 443 块（直连）
location /launcher/ {
    alias /opt/rainbow-site/launcher/;
    add_header Cache-Control "no-cache";
}

# 127.0.0.1:80 块（Cloudflare 隧道入口，公网实际走这个）
location /launcher/ {
    alias /opt/rainbow-site/launcher/;
    add_header Cache-Control "no-cache";
}
```

-- 库文件

/opt/rainbow-site/server/tools/launcher-release.js

## 4. 方案 A 操作步骤（发 0.2.1）

### 4.1 上传新文件

```bash
# 本地 → 服务器（文件名带 0.2.1，避免覆盖旧的）
scp RAINBOWMC-0.2.0-setup.exe root@<服务器>:/root/build/RAINBOWMC-0.2.1-setup.exe

# 服务器上核对哈希（必须与下面完全一致）
sha256sum /root/build/RAINBOWMC-0.2.1-setup.exe
# 期望：fa9521e09dce42717e51f66aa37c3358103021b7d083eaa87814e0a5506ad529
stat -c %s /root/build/RAINBOWMC-0.2.1-setup.exe
# 期望：81852307
```

### 4.2 登记发布

```bash
cd /opt/rainbow-site/server

node tools/launcher-release.js --add \
  --channel stable \
  --version 0.2.1 \
  --code 21 \
  --file /root/build/RAINBOWMC-0.2.1-setup.exe \
  --notes "修复安装器静默安装卡死、许可页乱码、语言选择、安装目录被覆盖的问题"

node tools/launcher-release.js --list
```

期望看到两行：`0.2.1 / 21` 与 `0.2.0 / 20`。

### 4.3 立刻验证公网接口

```bash
curl -s -H "X-Launcher-Channel: stable" \
     -H "User-Agent: RAINBOWMC/0.1.0 (win32; x64)" \
     https://rainbowdoor.icu/api/launcher/version | python3 -m json.tool
```

必须满足：

```
latest.version      = "0.2.1"
latest.versionCode  = 21
latest.downloadUrl  以 RAINBOWMC-0.2.1-setup.exe 结尾
latest.sha256       = fa9521e09dce42717e51f66aa37c3358103021b7d083eaa87814e0a5506ad529
latest.size         = 81852307
```

### 4.4 验证文件真的能下（关键：别下成首页 HTML）

```bash
curl -s https://rainbowdoor.icu/launcher/RAINBOWMC-0.2.1-setup.exe | head -c 2
# 必须输出 MZ ；输出 <! 说明 nginx 的 80 块没配

curl -sI https://rainbowdoor.icu/launcher/RAINBOWMC-0.2.1-setup.exe
# 期望：HTTP/2 200 / content-type: application/octet-stream
#       content-length: 81852307 / accept-ranges: bytes

# 断点续传检查
curl -s -o /dev/null -w "%{http_code}\n" -r 0-1023 \
  https://rainbowdoor.icu/launcher/RAINBOWMC-0.2.1-setup.exe
# 期望：206
```

### 4.5 可选：把 0.2.0 标记为非活跃

```bash
node tools/launcher-release.js --disable 2
```

> 不必须 —— 接口只返回 version_code 最大的那条。留着方便回滚。

## 5. 方案 B 操作步骤（原地替换 0.2.0）

### 5.1 备份现有文件与数据库

```bash
cd /opt/rainbow-site
cp launcher/RAINBOWMC-0.2.0-setup.exe launcher/RAINBOWMC-0.2.0-setup.exe.bak.$(date +%Y%m%d-%H%M)
cp server/data/rainbow.db server/backups/rainbow.db.bak.sha.$(date +%Y%m%d-%H%M)
```

### 5.2 覆盖文件

```bash
scp RAINBOWMC-0.2.0-setup.exe root@<服务器>:/opt/rainbow-site/launcher/RAINBOWMC-0.2.0-setup.exe

sha256sum /opt/rainbow-site/launcher/RAINBOWMC-0.2.0-setup.exe
# 期望：fa9521e09dce42717e51f66aa37c3358103021b7d083eaa87814e0a5506ad529
stat -c %s /opt/rainbow-site/launcher/RAINBOWMC-0.2.0-setup.exe
# 期望：81852307
```

### 5.3 更新数据库那条记录

```bash
sqlite3 /opt/rainbow-site/server/data/rainbow.db <<'SQL'
UPDATE launcher_releases
SET sha256 = 'fa9521e09dce42717e51f66aa37c3358103021b7d083eaa87814e0a5506ad529',
    size   = 81852307,
    notes  = '修复安装器静默安装卡死、许可页乱码、语言选择、安装目录被覆盖的问题'
WHERE channel = 'stable' AND version = '0.2.0' AND version_code = 20;

SELECT id, channel, version, version_code, size, sha256, is_active
FROM launcher_releases ORDER BY version_code DESC;
SQL
```

### 5.4 验证（同 4.3 / 4.4，URL 仍为 0.2.0）

```bash
curl -s https://rainbowdoor.icu/api/launcher/version | python3 -m json.tool | grep -E 'version|sha256|size'
curl -s https://rainbowdoor.icu/launcher/RAINBOWMC-0.2.0-setup.exe | head -c 2   # 必须是 MZ
```

## 6. 一定要做的事：刷 Cloudflare 缓存

```bash
# 有 API Token 的话
curl -X POST "https://api.cloudflare.com/client/v4/zones/<ZONE_ID>/purge_cache" \
     -H "Authorization: Bearer <TOKEN>" \
     -H "Content-Type: application/json" \
     --data '{"files":["https://rainbowdoor.icu/api/launcher/version","https://rainbowdoor.icu/launcher/"]}'
```

或者直接在 Cloudflare 后台 → Caching → Purge Everything。

> 不刷的话，客户端可能拿到旧的 `sha256` + 新的文件 → **必然校验失败**。

---

## 7. 回滚

```bash
# 方案 A 回滚：停用 0.2.1
node tools/launcher-release.js --disable 3

# 方案 B 回滚：恢复备份文件 + 恢复数据库记录
cp /opt/rainbow-site/launcher/RAINBOWMC-0.2.0-setup.exe.bak.* \
   /opt/rainbow-site/launcher/RAINBOWMC-0.2.0-setup.exe
sqlite3 /opt/rainbow-site/server/data/rainbow.db \
  "UPDATE launcher_releases SET sha256='f11bc1e563fdc4125bb1d06cfb0ef35658d2592fae0ea91648976ac5bfd4223c', size=81849698 WHERE version_code=20;"
```

---

## 8. 客户端拿到之后的预期行为

```
1. 启动 → GET /api/launcher/version → 看到 0.2.1(21) 或 0.2.0(20)
2. 本地 versionCode 更小 → 弹「发现新版本」
3. 点「立即更新」→ 下载 → 校验 sha256 → 不一致会删除并提示重试
4. 校验通过 → 弹出安装程序界面（不是静默安装）
   · 首次会弹「Installer Language」选择框（默认繁體）
   · 许可页中文正常显示
   · 覆盖安装不会动 data\（存档、模组、组件库）
5. 安装完成页点击完成后启动器自动打开
```
