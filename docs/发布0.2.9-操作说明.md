# 发布 0.2.9（安装器严重数据丢失修复）

> 日期：2026-10-22
> 读者：彩虹门社团网站 AI / 运维
>
> **这是安装脚本的严重 bug，0.2.7 / 0.2.8 的安装包会在特定路径下删除整个 `data/`（存档、组件库、配置）。**
> 0.2.9 已修复并在本机复现该路径验证通过。

---

## 1. bug 是什么

`build/installer.nsh` 的 `customInstall` 里我写了：

```
RMDir /r "$INSTDIR\data"      ← 先把 data 删掉，再从备份恢复
```

问题：**旧版安装包的卸载程序已经先把备份还原回 `data` 了**，这时再 `RMDir /r` 就把用户数据删干净了。
随后“从备份恢复”发现备份已被消耗 → 什么也没恢复。

实机后果（本机复现）：升级后 `data/` 只剩一个空目录骨架，11 个项目 / 4.7 GB 数据全没。

**触发条件**：用 0.2.7 或 0.2.8 的安装包去覆盖一个「数据还在 `data/` 里」的安装。
用 0.2.5 及更早、或 0.2.9 的安装包不受影响。

---

## 2. 0.2.9 怎么修的

1. **删掉了所有对 `data` 的删除动作**
   - `data` 不存在 → 用 `Rename` 把备份还回来（瞬间）
   - `data` 已存在（旧卸载程序已经还原过）→ 用 `robocopy /E /MOVE` **合并**，不删任何东西
2. **加最后一道保险**：如果数据没能挪走，安装器**中止安装**并弹窗提示，绝不执行 `RMDir /r $INSTDIR`

```
检测到 data 目录（存档 / 组件库）无法移动，安装已中止。
你的存档没有被删除。请完全退出 RAINBOW MC 后重试。
```

---

## 3. 本机验证（复现最危险路径）

```
① 装 0.2.8（旧安装器，含缺陷）
② 造数据：data/games/存档A、存档B、data/libraries/mods/z.jar
③ 用 0.2.9 安装包覆盖安装

结果：
  升级后目录：存档A, 存档B
  saveA=True  saveB=True  lib=True
  版本：0.2.9
  无残留 *-data-backup
```

另外还验证了：

| 场景 | 结果 |
|---|---|
| 0.2.9 → 0.2.9 覆盖（4.7 GB 数据） | 7 秒完成，数据完整 |
| 0.2.8 → 0.2.9（危险路径） | 存档/组件库完整 |

## 7. 给还在 0.2.7 / 0.2.8 的用户

- **不要再通过启动器内部更新**（那会用 0.2.7/0.2.8 的安装包，有丢数据风险）
- 请**手动下载 0.2.9 安装包**双击安装一次（这一次用的是 0.2.9 的安装器，安全）
- 装完后自动更新链路恢复正常

需要的话可以在网站发个公告说明这一点。
