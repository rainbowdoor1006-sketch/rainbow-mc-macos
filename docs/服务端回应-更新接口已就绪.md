## 2. 回答你的 6 个问题

### Q1. 版本数据写死还是后台管理？

**数据库表 + 命令行工具**，暂不做网页管理页。

```sql
launcher_releases (
  id, channel, version, version_code, file_name,
  sha256, size, notes, mandatory, min_supported,
  is_active, published_at
)
```

发布方式：

```bash
cd /opt/rainbow-site/server

# 查看已发布版本
node tools/launcher-release.js --list

# 发布新版本（sha256 与 size 自动计算，文件自动复制到 /opt/rainbow-site/launcher/）
node tools/launcher-release.js --add \
  --channel stable \
  --version 0.2.0 \
  --code 20 \
  --file /root/build/RAINBOWMC-0.2.0-setup.exe \
  --notes "修复整合包导入加载器未安装的问题"

# 撤回某版本
node tools/launcher-release.js --disable 2
```

`--list` 实际输出：

```
id   渠道       版本        code   大小          强制    启用    发布时间
------------------------------------------------------------------------
1    stable   0.1.0     10     71.1 MB     否     是     2026-10-22 01:56:45
```

> 网页管理页可以后续加，但**你的客户端不需要等它** —— 接口已经能用了。

### Q2. 是否支持 channel？

**支持。** `stable` / `beta` 两个渠道独立存储、独立取最新。

```
Header  X-Launcher-Channel: stable | beta
Query   ?channel=stable | beta          （Header 优先）
缺省    stable
异常值  一律按 stable 处理
```

> 现在只有 `stable` 有数据，`beta` 返回 `E9101`。
> 需要 beta 时我按你的灰度节奏发一条就行。

### Q3. downloadUrl 用直链还是带鉴权？

**直链，无鉴权。**

```
https://rainbowdoor.icu/launcher/RAINBOWMC-<version>-setup.exe
```

**理由：**
- 安装包本身不含秘密，公开可下没风险
- 不需要给客户端发凭证，少一个失败点
- 走 Cloudflare，天然带 CDN 缓存与 DDoS 防护

> 如果你后面确实需要「只允许启动器下载」，我再加带时效签名的 URL，
> 但那会引入时钟偏差、签名过期等新问题，**现在不建议**。

### Q4. 托管在哪？带宽够不够？

**托管：同一台阿里云 ECS**（`/opt/rainbow-site/launcher/`），走 Cloudflare 回源。

| 文件 | 大小 | 结论 |
|---|---|---|
| 启动器安装包 | **~75 MB** | ✅ 完全没问题，单文件直链够用 |
| 整合包（你说的 1.55 GB） | 1.55 GB | ⚠️ **不建议放在这台 ECS 上** |

**1.55 GB 为什么不行：**
```
· ECS 带宽通常是 3–5 Mbps 峰值，Cloudflare 回源会被打满
· 下载一个 1.55 GB 的包，在 5 Mbps 下要 40 多分钟
· 一旦有 3–5 个人同时下，整站都会变慢
· 走 Cloudflare 免费版对单个大文件有缓存与超时限制
```

**建议：**
- **启动器安装包**（75 MB）→ 放这台 ECS 就行，不用改
- **整合包（>200 MB）** → 上传到**阿里云 OSS + CDN**，`downloadUrl` 指向 OSS 直链
- 你今天不用管，等真有整合包要发时再说，我可以帮你接 OSS

### Q5. 是否需要强制更新（mandatory）？

**支持，接口字段已有**，触发条件由**你**定。

```bash
# 发布时加 --mandatory 就是强制更新
node tools/launcher-release.js --add ... --mandatory
```

接口返回 `"mandatory": true` 时，你的客户端就不显示「不用了，谢谢」。

**我建议的触发条件（仅供参考）：**
```
· 旧版本存在**登录失效**或**存档损坏**类 bug → mandatory
· 只是功能增强、修小 bug → 不强制
· minSupported 用于「低于这个版本必须升」，比 mandatory 更细
```

## 3. 三处需要你注意的差异

### 3.1 `versionCode` 的口径必须和我们一致

我按 **`MAJOR * 100 + MINOR * 10 + PATCH`** 发布的：

| 版本 | versionCode |
|---|---|
| `0.1.0` | **10** |
| `0.1.1` | 11 |
| `0.2.0` | **20** ✓ 和你文档 §1.1 例子一致 |
| `1.0.0` | 100 |

**你的客户端里本地 `versionCode` 也必须是 10**，否则第一次启动就会误判「落后」或「超前」。

如果你的客户端现在是从 `package.json` 的 `version` 字段字符串比较，
建议改成一个固定的常量或按上面公式算出来。

### 3.2 `publishedAt` 的时区

返回的是 **`2026-10-22 01:56:45`**（北京时间，无时区后缀），
**不是你文档里写的 ISO 8601 `2026-11-01T12:00:00+08:00`**。

如果你想严格用 ISO，告诉我，我改格式。
不过这个字段客户端一般只用来显示「发布时间」，两种都能解析。

### 3.3 `latest.version` 严格 `MAJOR.MINOR.PATCH`

发布时服务端会校验：

```js
if (!/^\d+\.\d+\.\d+$/.test(version)) throw new Error('必须是 MAJOR.MINOR.PATCH');
```

`v0.2.0`、`0.2.0-beta`、`0.2` 都会被拒绝。**和你的要求一致** ✅

## 6. 一个坑，记下来免得你踩

**nginx 有两个 server 块**：443（直连）和 127.0.0.1:80（Cloudflare 隧道入口）。
我在 443 块加完 `location /launcher/` 后，公网下载**仍然返回首页** —— 因为
公网流量走的是 **Cloudflare → 隧道的 80 块**，而 80 块没这个 location。

**所以你以后让我加任何静态目录，都要提醒我「两个块都要加」。**
